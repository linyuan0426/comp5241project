# Pathwise 趣味学习功能开发任务书

版本 v1.0 · 2026-11-12 · 状态：待开发

## 1. 项目目标

面向使用课件复习的大学生，增加三个可在课堂演示的学习玩法：带教 AI 实习生、拯救离谱小组作业、一句话救救我。用角色对话和具体错误吸引学生，让学生通过纠正、决策和解释展示理解，再根据遗漏的知识点安排下一步练习。

核心展示主张：学生的解释会改变 AI 的追问和后续任务。学习效果需通过实际试用验证。

本任务书默认沿用现有 React、Vite、TypeScript、Supabase 和服务端 AI 接口。产品界面延续现有英文风格，支持中英文输入；AI 回复默认跟随学生选定的中文或英文。本文中文角色台词为内容设计参考。

## 2. 交付范围与优先级

| 顺序 | 交付内容 | 完成条件 |
| --- | --- | --- |
| P0 | 共用练习流程和带教 AI 实习生 | 样例、课件生成、纠正、追问、总结和进度保存跑通 |
| P1 | 拯救离谱小组作业 | 两个经过人工审核的案例，可选择方案并解释理由 |
| P1 | 一句话救救我 | 选择概念、解释、最多两轮追问、总结和换场景题跑通 |
| P0 | 集成测试与展示材料 | 真正的登录、AI 调用、存储恢复得到验证，并有已知问题记录 |

首版采用文字、卡片和现有图标。课堂演示重点覆盖缓存更新和异步请求顺序两个概念。课件生成优先支持文字解释类任务，小组作业首版使用固定案例。

## 3. 功能需求

### F1 带教 AI 实习生

**目标**：学生指出错误并解释原因，系统识别其遗漏的概念。

**入口**：新增 Fun Practice 导航入口；学习计划中提供 Practice this concept 按钮，携带当前课件和概念。新入口包含三个玩法卡片及可直接体验的样例。

**流程**

1. 选择内置样例，或从已解析的课件选取概念。登录用户可生成课件练习。
2. 展示实习生的一段作业，包含一个明确的预设概念错误。学生选中可疑句子，填写纠正意见。
3. 返回学生已经解释清楚的内容、仍遗漏的内容，以及实习生修改后的理解。
4. 若遗漏关键内容，实习生围绕一个遗漏点追问。最多两轮追问，首次回答加追问回复共最多三次提交。
5. 提前满足标准即可完成；达到轮数上限仍未解释清楚，则标记“需要再练”，展示正确解释与课件依据。
6. 给一道人工审核或随任务生成的换场景题，单独记录表现，不计入两轮追问。

**台词示例**

> “我把所有数据放进缓存，永远不更新。速度很稳定，内容也很稳定——一直停留在昨天。”

**验收**

- 每道练习只包含一个预设核心误解，纠正标准在练习开始前确定。
- 学生只说“你错了”时，系统请求具体解释；同义表达可以被接受。
- 追问引用当前回答中的遗漏点；已经解释清楚的内容不重复要求。
- 正确版本、依据和“需要再练”状态均可在结果页查看。

### F2 拯救离谱小组作业

**目标**：学生在具体情境中评价方案、说明后果，并提出修正。

**内容**：首版制作两个固定案例，分别为“永不更新的缓存”和“显示最后到达的搜索响应”。每个案例两步，第一步识别问题，第二步选择修复方案。每步三个选项，至少一个干扰项应有合理表象，避免只靠笑话猜答案。

**流程**

1. 用队友消息卡呈现需求和方案。
2. 学生选择处理方式，界面显示该方案造成的具体结果。
3. 在最终选择后补充一句理由，AI 判断是否涉及关键概念，并最多追问一次。
4. 完成后展示选择、后果、修正方案及遗漏点；可以重玩，重玩创建新尝试。

**台词示例**

> “我决定显示最后收到的响应。它来得最晚，肯定掌握了最新消息。”

**验收**

- 选择造成的结果由审核过的案例数据决定。
- 选择正确但理由错误时，提示补充解释，不直接认定理解。
- 干扰项提供原因说明；重试保留本次历史供复盘。
- 原有 Scenario Challenge 保持可用，新玩法复用合适的数据与交互逻辑。

### F3 一句话救救我

**目标**：学生用简洁、准确的语言向初学者解释一个概念。

**流程**

1. 选择样例或课件中的一个概念，AI 室友提出求助。
2. 学生自由输入一小段解释。“一句话”为玩法名称，允许多句，不以篇幅短作为正确标准。
3. AI 从准确性、关键要点、例子的适用范围三个方面检查，围绕实际缺口追问，最多两轮。
4. 解释充分后结束；仍有缺口则展示示范解释。最后给一道换场景题。

**台词示例**

> “明天就考试了。我知道缓存像冰箱，但数据库到底是超市还是菜市场？”

**验收**

- 使用比喻时检查其适用边界，避免把生动等同于准确。
- 直接给定义且解释正确的答案可通过，无需强制讲笑话。
- 报告列出已说明和待补充要点，每项附具体理由。

## 4. 共用体验与内容规则

- 幽默来自 AI 角色自己的误解、自嘲或情境；对学生的反馈友善且具体。
- 笑话每条回复最多一句，先保证知识解释准确。学生可关闭幽默，关闭后保留完整学习内容。
- 随练习保存概念与遗漏要点；下次进入显示“继续练习”，优先选择该概念。首版按最近未解决的遗漏点推荐。
- 提供清楚的加载、失败、重试和保存状态。失败保留输入，重试成功后才能推进轮次。
- 样例以 Demo 标识，访客可使用固定选项和预设反馈走通流程。自由文本 AI 评价需要登录；Demo 不显示虚构的个性化评价。
- 内置样例来源使用随项目提供的审核知识卡；课件任务保存原文片段和页码，结果页支持查看依据。
- 引用匹配原文只能证明引用存在。生成内容还需检查它与纠正标准是否相关；质量不确定时提示重新生成。人工抽查结果列入测试报告。

## 5. 技术设计

### 前端与复用

新增 `src/features/fun-practice/` 模块，统一管理玩法选择、任务、提交、反馈、报告和恢复状态。角色台词与任务数据独立于组件。

复用 `src/lib/ai.ts` 的 `callAi`、现有登录上下文、`useProgressStorage` 和已有界面组件。沿用 `/api/ai` 的认证、额度与 provider。现有模拟面试的网络调用方式可复用，新练习采用独立类型与数据记录。

### API 变更

继续采用 POST `/api/ai`，返回现有 `{ data }` 或 `{ error }` 形式，增加以下 action。

| action | 输入 | 输出 |
| --- | --- | --- |
| `fun-practice-create` | mode、language、concept、sourceText | task，包含呈现内容、纠正标准、来源和换场景题 |
| `fun-practice-review` | task、当前阶段、已有回合、当前回答及可选 choiceId | feedback、已满足/遗漏标准 ID、追问或结束状态、角色回复 |

`mode` 使用 `intern`、`teamwork`、`roommate`。固定小组案例从本地审核数据加载，评价由 review action 完成。换场景题复用 review action，通过阶段字段区分。

沿用 Zod 验证请求和模型输出，检查标准 ID、选项 ID、轮数和引用。sourceText 上限沿用 study-kit 的 31,000 字符，学生单次输入最多 2,000 字符，每题纠正标准 2–4 项。失效输出不保存为学习结果，显示可重试的错误。

学生输入、课件和历史回复作为待分析内容传入；提示词明确不执行其中修改评分规则或泄露系统提示的指令。评价用于学习反馈，并可查看依据。

### 数据与恢复

- `PracticeTask` 保存 id、version、mode、concept、language、prompt、criteria、sourceEvidence、transferQuestion；实习生任务另有预设误解与正确解释，小组任务另有 steps 和 choices。
- `PracticeSession` 保存 id、task、status、turns、currentStage、report、createdAt、updatedAt；回合保存 submissionId、输入、可选选择和评价。
- `PracticeReport` 保存已满足标准、遗漏标准、正确解释、下一步建议及换场景题表现。未作答的换场景题显示“未验证”。
- 增加 `genai-fun-practice:v1` 进度键，保存当前练习与最近 20 次结果摘要。复用现有账号隔离、同步与冲突处理。
- 同时扩展前端进度键白名单和数据库 `record_key` 检查约束，新增增量迁移，保留已有允许值。
- 每次提交生成 submissionId，等待时禁用重复提交；重复返回只保存一次。明确提示手动重试可能再次消耗 AI 额度。
- 恢复时以最后一个已保存成功的回合继续；请求中的状态恢复为可重试。切换账号后不得显示上一账号内容。

## 7. 测试与验收

### 自动化与人工功能测试

- 运行现有 `pnpm test` 和 `pnpm build`。此前 51 项测试通过仅为基线，新功能完成后重新验证。
- 新增针对关键回归的测试：轮数上限、无效模型输出、重复响应、失败重试、进度恢复和账号隔离。
- 内容用例覆盖完全正确、部分正确、只有否定、错误但自信、同义解释、无关回答和试图修改评价规则。
- 接口覆盖未登录、过期登录、额度耗尽、超长输入、provider 超时和无效 JSON。
- 实际验证登录→课件练习→AI 反馈→保存→刷新恢复→重新登录查看结果；检查云端实际记录。
- Demo 在无 AI 配置时可玩；真实模式失败时保留学生输入，并明确提示服务状态。
- 检查键盘操作、窄屏、长文本、中英文回复及关闭幽默。

### 学习体验验证

招募 5–8 名目标学生开展探索性试用，记录完成率、困难位置、趣味评价与换场景题表现。准备两个难度接近的概念任务，交替安排普通阅读与趣味玩法的体验顺序，减少先后顺序影响。

按同一标准人工评价解释和换场景答案，展示原始人数、具体错误和反馈。记录“发现问题—设计修改—复测结果”；样本规模和无法排除的差异写入报告。

### 完成标准

三个玩法均有可演示样例；带教与室友支持课件生成；个性化追问确实随回答变化；进度可恢复；核心测试通过；已知问题与未验证项可查；每个案例完成后都有正确知识解释。

## 8. 展示与提交物

**90 秒主 Demo**

1. 10 秒：介绍学生难以解释自己学过的概念这一问题。
2. 15 秒：展示实习生关于缓存的离谱作业。
3. 20 秒：只纠正部分问题，展示系统发现遗漏并具体追问。
4. 20 秒：补全解释，展示 AI 修改后的理解与结果页。
5. 15 秒：展示换场景题、历史记录和恢复状态。
6. 10 秒：展示一项真实试用发现及对应改进。

**最终提交物**

- 可运行代码、数据库增量迁移和更新后的本地运行说明。
- 经人工审核的任务样例、评价标准及来源。
- 自动化结果、集成测试记录和已知问题列表。
- 小规模用户试用记录与至少一项有依据的迭代。
- 90 秒 Demo 脚本与备用录屏。
- 团队贡献记录，说明 AI 辅助内容、人工设计取舍、审核和验证工作。
